# 線上書店產品需求文件

## 產品概述

本產品為**簡單無需登入的線上書店**，提供用戶流暢的購書體驗。用戶可以瀏覽書籍、加入購物車、填寫訂單資訊並完成購買，整個流程無需註冊或登入帳號。

### 核心價值主張
- **零摩擦購書體驗**：無需註冊即可購買，最大化轉換率
- **簡化結帳流程**：一步式結帳，減少購物車放棄率
- **行動優先設計**：響應式設計，適用於手機、平板、桌機
- **快速載入**：優化圖片載入和分頁機制

## 用戶故事

### 故事 1：瀏覽書籍目錄 (優先級：P1)

**身為** 書籍買家  
**我希望** 瀏覽可購買的書籍及其詳細資訊和圖片  
**以便** 發現並選擇想要購買的書籍  

**為什麼是最高優先級**：這是電商的核心功能，用戶必須能夠看到商品才能產生購買行為。

**獨立測試方式**：用戶能夠訪問首頁並看到書籍列表，可以瀏覽不同頁面的書籍。

#### 驗收場景

1. **當** 用戶訪問首頁 **則** 系統應顯示分頁的書籍網格，每行顯示 5 本書
2. **當** 顯示每本書 **則** 系統應顯示書籍封面圖片、標題（過長時截斷）、作者和美金價格格式 ($XX.XX)
3. **當** 用戶點擊"第一頁"、"上一頁"、"下一頁"或"最後一頁"分頁控制 **則** 系統應導航到對應的結果頁面
4. **當** 書籍標題超過顯示寬度 **則** 系統應用省略號截斷並在滑鼠懸停時顯示完整標題（工具提示）
5. **當** 用戶點擊書籍上的"購買"按鈕 **則** 系統應將該書加入購物車並跳轉到購物車/結帳頁面

### 故事 2：購物車管理 (優先級：P1)

**身為** 書籍買家  
**我希望** 檢視購物車中的商品並調整數量  
**以便** 在下單前確認我的購買內容  

**為什麼是最高優先級**：購物車是完成購買前的必要步驟，用戶需要確認和調整購買內容。

**獨立測試方式**：用戶能夠看到已加入的商品、修改數量、查看總金額。

#### 驗收場景

1. **當** 用戶點擊"購買"後跳轉到購物車頁面 **則** 系統應顯示購物車內容，包含商品名稱、價格、數量輸入框和小計
2. **當** 購物車包含商品 **則** 系統應顯示表格，欄位包括：商品名稱、價格、數量、小計
3. **當** 用戶更改數量輸入框 **則** 系統應更新購物車商品數量並重新計算小計和總金額
4. **當** 計算購物車總額 **則** 系統應在購物車表格下方顯示"總金額：$XX.XX"
5. **當** 購物車為空 **則** 系統應顯示"您的購物車是空的。繼續購物"訊息，並提供回到商品頁面的連結
6. **當** 購物車載入失敗 **則** 系統應顯示"目前無法載入您的購物車。繼續購物"訊息
7. **如果** 購物車至少包含一項商品 **則** 系統應在購物車下方顯示訂單表單

### 故事 3：訂單表單和結帳 (優先級：P1)

**身為** 書籍買家  
**我希望** 輸入我的配送資訊並下訂單  
**以便** 完成購買並收到書籍  

**為什麼是最高優先級**：這是購買流程的最終步驟，沒有這個功能就無法完成交易。

**獨立測試方式**：用戶能夠填寫配送資訊、提交訂單並收到訂單確認。

#### 驗收場景

1. **當** 購物車包含商品 **則** 系統應顯示訂單表單，欄位包括：客戶姓名、客戶信箱、客戶電話、配送地址
2. **當** 用戶提交訂單表單 **則** 系統應驗證所有必填欄位是否已填寫
3. **如果** 客戶信箱格式無效 **則** 系統應在信箱欄位下方顯示"資料不正確"錯誤訊息，並將欄位邊框設為紅色
4. **如果** 任何必填欄位為空 **則** 系統應阻止表單提交並顯示驗證錯誤
5. **當** 所有欄位有效且用戶點擊"下訂單" **則** 系統應提交訂單
6. **當** 訂單成功建立 **則** 系統應將用戶跳轉到訂單確認或訂單列表頁面
7. **當** 訂單提交失敗 **則** 系統應在表單頂部顯示錯誤警告訊息

**表單欄位需求**：
- 客戶姓名：必填文字輸入，無長度限制
- 客戶信箱：必填信箱輸入，具備 HTML5 信箱驗證
- 客戶電話：必填文字輸入（第一階段無格式驗證）
- 配送地址：必填文字輸入，完整地址

### 故事 4：訂單歷史檢視 (優先級：P2)

**身為** 書籍買家  
**我希望** 檢視我所有過往的訂單及其狀態  
**以便** 追蹤我的購買記錄  

**為什麼是次要優先級**：雖然有用，但不是完成購買的必要功能，可以在核心購買流程完成後再實作。

**獨立測試方式**：用戶能夠查看訂單列表、點擊訂單號碼查看詳細資訊。

#### 驗收場景

1. **當** 用戶導航到訂單頁面 **則** 系統應顯示表格，欄位包括：訂單編號、狀態
2. **當** 顯示訂單 **則** 系統應以時間倒序顯示所有訂單（最新的在前）
3. **當** 顯示訂單編號 **則** 系統應將其呈現為可點擊的連結，連到訂單詳細頁面
4. **當** 用戶點擊訂單號碼連結 **則** 系統應導航到訂單詳細頁面 (/orders/{orderNumber})
5. **如果** 訂單載入失敗 **則** 系統應顯示錯誤警告及錯誤訊息
6. **當** 沒有訂單存在 **則** 系統應顯示空狀態訊息

### 故事 5：網站導航和標題列 (優先級：P2)

**身為** 書籍買家  
**我希望** 在目錄和訂單之間輕鬆導航  
**以便** 瀏覽書籍並檢查我的訂單狀態  

**為什麼是次要優先級**：導航很重要，但用戶可以透過瀏覽器的前進/後退或直接輸入網址來導航。

**獨立測試方式**：用戶能夠透過標題列在不同頁面間導航。

#### 驗收場景

1. **當** 用戶在任何頁面 **則** 系統應顯示網站標題列，包含"BookStore"品牌標誌和"訂單"連結
2. **當** 用戶點擊"BookStore"標誌 **則** 系統應導航到商品頁面 (/)
3. **當** 用戶點擊標題列中的"訂單"連結 **則** 系統應導航到訂單列表頁面 (/orders)
4. **當** 顯示標題列 **則** 系統應使用深色背景 (#212529 或類似色彩) 搭配白色文字

## 邊緣案例和錯誤處理

### 網路和載入錯誤

1. **書籍載入失敗**
   - **場景**：API 無回應或伺服器錯誤
   - **預期行為**：顯示"無法載入書籍。請稍後再試。"錯誤訊息
   - **用戶操作**：提供"重新載入"按鈕

2. **購物車載入失敗**
   - **場景**：購物車 API 無法存取
   - **預期行為**：顯示"目前無法載入您的購物車。繼續購物"
   - **用戶操作**：提供返回商品頁面的連結

3. **訂單提交失敗**
   - **場景**：網路中斷或伺服器錯誤
   - **預期行為**：顯示"下訂單失敗。請稍後再試。"
   - **用戶操作**：允許用戶重新提交，資料保留在表單中

### 資料驗證錯誤

1. **無效的電子信箱格式**
   - **場景**：用戶輸入格式錯誤的信箱
   - **預期行為**：即時顯示"信箱格式不正確"，欄位邊框變紅色
   - **用戶操作**：用戶修正格式後錯誤訊息消失

2. **必填欄位為空**
   - **場景**：用戶未填寫必填資訊就提交
   - **預期行為**：阻止提交，顯示"此欄位為必填"
   - **用戶操作**：填寫完整後才能提交

3. **無效的數量輸入**
   - **場景**：用戶在購物車輸入 0 或負數
   - **預期行為**：自動調整為 1，或顯示"數量必須大於 0"
   - **用戶操作**：輸入有效數量

### 空狀態處理

1. **空的購物車**
   - **場景**：用戶直接訪問購物車頁面但沒有商品
   - **預期行為**：顯示"您的購物車是空的。繼續購物"
   - **用戶操作**：提供返回商品頁面的按鈕

2. **沒有訂單歷史**
   - **場景**：新用戶或從未下過訂單
   - **預期行為**：顯示"您還沒有任何訂單"
   - **用戶操作**：提供"開始購物"按鈕

3. **找不到訂單**
   - **場景**：用戶訪問不存在的訂單編號
   - **預期行為**：顯示"找不到此訂單"頁面
   - **用戶操作**：提供返回訂單列表的連結

### 載入狀態

1. **書籍載入中**
   - **預期行為**：顯示 5 個書籍卡片的骨架畫面或載入轉圈
   - **時間限制**：如果超過 10 秒，顯示錯誤訊息

2. **購物車更新中**
   - **預期行為**：數量輸入框顯示載入狀態，暫時停用
   - **時間限制**：如果超過 5 秒，顯示錯誤並恢復原始數量

3. **訂單提交中**
   - **預期行為**："下訂單"按鈕顯示載入轉圈，暫時停用
   - **時間限制**：如果超過 15 秒，顯示超時錯誤

### 瀏覽器相容性

1. **舊版瀏覽器**
   - **場景**：不支援某些現代功能的瀏覽器
   - **預期行為**：降級到基本功能，但核心購物流程必須可用

2. **JavaScript 停用**
   - **場景**：用戶停用 JavaScript
   - **預期行為**：顯示"需要啟用 JavaScript 才能使用此網站"訊息

### 行動裝置特殊情況

1. **觸控操作**
   - **場景**：在小螢幕上操作
   - **預期行為**：所有按鈕至少 44x44px，易於點擊
   - **用戶操作**：手指觸控不會誤觸其他元素

2. **螢幕方向改變**
   - **場景**：用戶旋轉手機
   - **預期行為**：版面自動調整，不影響使用體驗

3. **慢速網路**
   - **場景**：3G 網路環境
   - **預期行為**：圖片延遲載入，優先顯示文字內容

## 成功指標

### 業務指標
- **轉換率**：訪問到購買的轉換率目標 >3%
- **購物車放棄率**：<70%（行業平均約 70-80%）
- **頁面載入時間**：首頁 <2 秒，其他頁面 <3 秒
- **行動使用率**：>60% 的用戶透過行動裝置完成購買

### 用戶體驗指標
- **任務完成率**：>95% 的用戶能成功完成購買流程
- **錯誤率**：<5% 的交易因為用戶錯誤而失敗
- **用戶滿意度**：透過簡單調查，滿意度 >4/5

### 技術指標
- **可用性**：>99.5% 的時間可正常使用
- **錯誤率**：<1% 的 API 請求失敗
- **響應時間**：API 響應時間 <500ms
